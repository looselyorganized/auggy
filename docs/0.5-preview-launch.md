# 0.5 Public Preview Launch

This is the launch-readiness checklist for the `0.5.0` app-backend preview.
Use [`RELEASING.md`](./RELEASING.md) for the mechanical release/tag/publish
process.

## Launch Posture

- npm package: public.
- Source repository: private during preview.
- License: Apache-2.0.
- npm provenance: off until the source repo is public.
- `repository` package metadata: omitted while the repo is private.
- Support path: `hello@looselyorganized.xyz` and launch-site contact paths.
- Positioning: public preview, not public OSS repository.

## Release Timing

Package manifests and changelog have been prepared for `0.5.0`. Do not publish
npm packages until the final launch approval. Remaining release steps:

1. Run the release rehearsal gates.
2. Merge the release PR/commit.
3. Tag `v0.5.0`.
4. Let the publish workflow publish npm packages.

## Package Readiness

- Root package metadata points to `https://auggy.dev`, not a private GitHub URL.
- Root and workspace package `bugs` metadata use the support email while the repo
  is private.
- The root npm tarball includes `README.md`, `CHANGELOG.md`, `LICENSE`, and
  `SECURITY.md`.
- The root npm tarball excludes local-only/internal material such as `.env`,
  `.git/`, `.auggy/`, `node_modules/`, `docs/`, and `tests/`.
- `npm pack --dry-run` and the release smoke pass before publish.

## Docs Readiness

- The root README explains Auggy as an agent-native app backend, not only a chat
  runtime.
- The first three preview use cases are visible:
  - authenticated SaaS app agent
  - booking/concierge/support backend
  - developer/docs assistant that generates implementation artifacts
- Public docs on `auggy.dev` should mirror the install path, quickstart, route
  clients, delegated authorization, and the two core examples before launch.
- Source docs may stay in the private repo, but npm users should not be sent to
  a private GitHub issue tracker or private repository page.

## Example Readiness

- `examples/concierge` proves the route/tool/domain pattern.
- `examples/app-auth-bridge` proves Supabase/Clerk-style app auth, generated
  browser clients, delegated route authorization, protected tool authorization,
  key rotation, and replay protection.
- Website demos should consume the same documented patterns rather than
  relying on private or one-off APIs.

## Website Handoff

Track A should make `https://auggy.dev` the public documentation and support
surface before `0.5.0` is published. Minimum launch pages:

- homepage with the app-backend thesis
- quickstart
- recipes or examples
- generated route clients
- delegated authorization
- live Auggy-powered proof surface when ready
