# 0.5 Runtime Public Preview Launch

This is the launch-readiness checklist for the `0.5.0` runtime-first public
preview. Use [`RELEASING.md`](./RELEASING.md) for tagging and publishing.

## Launch Posture

- Product: a small Bun/TypeScript runtime for self-hosted agents composed from
  augments.
- npm package: public.
- Source repository: private during preview.
- License: Apache-2.0.
- npm provenance: off until the source repository is public.
- Support: `hello@looselyorganized.xyz` and the public site contact path.
- Production guidance: public preview; pin exact versions before `1.0.0`.

## Release Timing

Package manifests and changelog are prepared for `0.5.0`. Do not publish until:

1. package, README, CLI, hosted docs, and site use the same runtime-first
   positioning,
2. release rehearsal gates pass,
3. the release commit is approved,
4. `v0.5.0` is tagged.

## Public Promise

The launch must make these points obvious:

- the kernel runs agent turns,
- augments add tools, memory, transports, context, skills, and policy,
- agents are ordinary portable TypeScript projects,
- a fresh agent can be created and used without understanding advanced
  architecture,
- routes and app integration are optional preview capabilities,
- Auggy is not currently a durable workflow engine or persistent job queue.

Do not publish roadmap timelines or make unfinished operational-agent features
part of the release promise.

## Package Readiness

- `package.json` description and keywords describe the agent runtime.
- CLI welcome copy matches the README.
- The root npm tarball includes `README.md`, `CHANGELOG.md`, `LICENSE`, and
  `SECURITY.md`.
- The tarball excludes `.env`, `.git/`, `.auggy/`, `node_modules/`, private
  docs, tests, local databases, and workspaces.
- `npm pack --dry-run` and the release smoke test pass.
- Provider adapter package versions are coordinated with the runtime package.

## First-Run Readiness

A new user can:

1. install `auggy`,
2. run `auggy create my-agent`,
3. add the requested provider key,
4. run `auggy run`,
5. chat through the local console,
6. identify enabled augments and their configuration,
7. create or add one augment,
8. run `auggy doctor`,
9. follow the Railway deploy path.

The default project stays chat-ready and does not require app auth, custom
routes, a database, or external messaging services.

## Documentation Readiness

- Root README leads with quickstart and the kernel/augment mental model.
- `docs/README.md` navigates current runtime documentation.
- `FEATURES.md` reports present status without acting as a public roadmap.
- Advanced route, generated-client, and delegated-auth docs are labeled
  preview and remain discoverable outside the primary path.
- Public docs do not link internal roadmaps or strategy plans.
- Public URLs referenced by the package resolve before publication.

## Example Readiness

- The default scaffold is the canonical first example.
- Custom augment documentation shows one small typed tool.
- MCP demonstrates external tool integration.
- Concierge and app-auth-bridge examples remain available as advanced preview
  integrations, not the primary product story.
- Every public example is verified from a fresh project or package install.

## Website Handoff

The paired `auggy-site` release must ship the same message. Minimum pages:

- homepage: small runtime plus composable augments,
- quickstart: install, create, run, chat,
- augments: core, stable add-ons, and preview add-ons,
- custom augment/tool guide,
- memory, MCP, console, and deploy references,
- advanced preview area for routes and delegated app integration.

Keep existing URLs where practical. Redirect removed or renamed pages rather
than leaving package links broken.

## Verification Gates

Before final approval:

```bash
bun test
bunx tsc --noEmit
bun run lint
bun run smoke:release
```

Also verify:

- fresh `auggy create` and first boot,
- `auggy doctor`,
- one custom augment scaffold and test,
- one MCP configuration,
- one Railway release rehearsal,
- package/site wording consistency.
