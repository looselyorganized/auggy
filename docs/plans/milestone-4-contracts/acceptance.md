# C4 — installed authoring acceptance and evidence

Proposed contract for the [M4 execution plan](../milestone-4-execution-2026-11-13.md).
Required rows are outcomes, not test-count targets. Each needs a command, actual
assertion, negative control, artifact identity and cleanup result.

## Actual generation is the oracle

M3's `application-install.ts` prepares a consumer by copying
`examples/inspectable-agent`. Retain that as a separate reference regression test;
it cannot certify M4 creation. Install the CLI and candidate packages from exact
tarballs into an isolated prefix/HOME, invoke the real binary from a directory
outside the checkout, and hash the generated output immediately.

Use existing exact-package-specifier seams during generation to select candidate
core/provider tarballs. Never repair a generated manifest afterward to conceal
broken package output. Record the seam and prove the ordinary emitted manifest
does not contain temporary tarball or checkout paths. Install the generated
manifest, record resulting lock/provenance and verify frozen reinstall.

Refactor the shared M3 execution runner only enough to accept an already-created
project and its recipe. Reuse bounded process supervision, artifact hashing,
HTTP/SSE/auth/replay assertions, source-edit tests and cleanup. Do not duplicate a
runtime, fake `TransportKernel`, or add product logging just to match the reference
fixture's trace format.

Enumerate allowed post-snapshot harness changes: dummy credentials, temporary
ports, loopback provider URL, isolated state paths where supported, deterministic
business fixture inputs, and explicit source edits being tested. Add custom test
capabilities through the real `augment create`/install path, recording subsequent
source edits separately. These changes must not replace startup, HTTP, composition
or turn source merely to get the baseline to run. Restore edits and demonstrate
baseline behavior returns; an incorrect expected marker must make the verifier fail.

Keep startup/HTTP/turn sensitivity across the five M3 launch paths (15 edit
observations) unless an accepted baseline difference changes that matrix. Test
domain-service customization separately. External package source navigation alone
does not prove generated source executes.

## Coverage without a combinatorial test explosion

- Generate/install/typecheck/audit each of Anthropic, OpenAI, OpenRouter and Ollama;
  assert selected provider and no incidental dependency on another provider.
- Use the existing real Anthropic adapter and bounded loopback Messages fixture
  for complete HTTP/tool/final/restart proof. Other provider contract tests remain;
  do not label the Anthropic fixture live certification of every provider.
- Deterministic Ollama responses cover installed discovery, empty list/unreachable
  service and remote credential policy. No model downloads or live credentials.
- Use one focused legacy corpus for semantics and fault injection, then an
  installed legacy-to-application fixture for real startup/durable replay. Use
  accepted safe package artifacts; historical folder shape does not require
  installing an old vulnerable dependency graph.
- Linux CI certifies Linux execution and deployment artifacts. Actual generated
  launchd start/status/stop/restart on macOS is distinct required evidence; rendered
  plist text is not macOS runtime proof. Unavailable platform evidence is recorded
  as unavailable and prevents claiming that acceptance row passed.
- Preserve SQLite single-replica behavior and PostgreSQL-disabled ordinary boot.
  Existing PG17 protocol tests still run in their required service lane; M4 adds
  no public coordination support.

## Review attacks and implementation guardrails

Independent review tries to falsify these claims:

1. The harness certifies untouched generator output, not a repaired reference.
2. The endpoint and local loop actually execute under all advertised launch paths.
3. Static inspection never imports customer/runtime implementations or materializes
   secrets; its paths describe the local installed package and declared state.
4. A second YAML/TS registry has not reappeared in a helper, skill or generated file.
5. Init, add, setup, migration and rollback cannot silently erase owned content.
6. Config activation/recovery stays valid under interruption and concurrent CLI
   operations; uncooperative editor limitations are honestly documented.
7. AgentMail's inline adaptation preserves authorization/transport/CAS semantics.
8. Source index packaging covers supported non-picker types and contains real paths.
9. Upgrade ownership evidence is genuine; same-version artifact swaps are labeled.
10. Documentation and CLI success messages state limitations/readiness accurately.

Retain M3's harness lessons: descriptor-based bounded evidence reads, static
fixture code with data passed separately, existing harness-shard isolation for
process mocks, actual script import/typechecks (root `src` typecheck is not enough),
and bounded ready/scenario/shutdown budgets (60/120/15 seconds currently). Redact
and bound logs, use dummy credentials/environment allowlists and private temp
directories, and always clean children/listeners in failure paths.

Do not reintroduce PG fixture leases shorter than the test's 30-second timeout or
weaken exact rejection assertions. Audit at all severities. A successful CodeQL
analysis job is not zero findings: the separate findings check must pass too.
Producer tests cannot replace independent review; reviewer repairs require a
different reviewer for the repaired code.

## Required certification and handoff

After focused tests, freeze the candidate and run the repository's required
inventory, strict typecheck/lint, runtime and console suites, generated/reference
consumer checks, package/prepack/source-index validation, full release rehearsal,
strict workspace/consumer audit, required PG17 zero-skip lane and CodeQL analysis
plus findings. Register new scripts/tests in the existing inventory/shard system;
do not rely on recursive test discovery or omit scripts from type verification.
Root owns final CI wiring and preserves every existing required gate.

Add an individually runnable generated-authoring smoke entry (root registers
`smoke:authoring`) and include it in the release rehearsal. It takes the same
candidate artifact set and evidence destination as the shared harness; no private
manual setup is needed. New fixtures/scripts get focused Bun tests for meaningful
failure detection, not tests that merely repeat implementation strings.

Record in the M4 evidence document: accepted main/base/tree, final source and
tested merge SHAs, dirty state, toolchain, root/consumer lock hashes, tarball hashes,
installed package paths/hashes, generated-byte snapshots, allowed mutations,
redacted commands, request correlation, provider/tool effects, edit controls,
migration preimages/outputs/recovery outcomes, retained-state hashes, cleanup,
platform outcomes, failed attempts and reviewer dispositions. No `.env`, auth
headers, inline-secret backups or unbounded logs in evidence.

Use `passed`, `failed`, `unavailable` and `not-run` distinctly. Repeat checks after
changes only as necessary to cover affected behavior and the final required
candidate; do not repeatedly run unchanged broad suites without a reason. A
local skipped PG lane cannot stand in for required zero-skip CI execution.

The final PR describes actual behavior/compatibility changes and links exact
verification. Root records remaining risks and rejects acceptance with any
unresolved blocking finding. Passing tests do not authorize npm publication,
automatic project regeneration or an unapproved merge.
